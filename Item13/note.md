# 항목 13: 자원관리에는 객체가 그만!
* 자원 누출을 막기 위해 생성자 안에서 자원을 획득하고 소멸자에서 그것을 해제하는 RAII객체를 사용합시다.
* 일반적으로 널리 쓰이 RAII 클래시는 *tr1::shared_ptr* 그리고 *auto_ptr(현재는 unique_ptr)*입니다. 이 둘 가운데 *tr1::shared_ptr*이 복사 시의 동작이 직관적이기 때문에 대개 더 좋습니다. 반면 *auto_ptr*은 복사되는 개체(원본 객체)를 null로 만들어 버립니다.(하지만 최근에는 사장됨. WHY? --> NULL로 만들어 버리는 것 때문에 segment fault가 떠서 인지용?)

### 실습 요약
1. 자원 획득 후 개발자가 실수하기 쉬운 return이나 try-catch, goto등 자원 해제(delete)를 할 수 없는 상황 연출
2. delete를 통한 자원 해제를 실패했기 때문에 개같이 메모리 누수 발생

* 
1. unique\_ptr를 통해 자원의 누출을 막고 생성자 안에서 자원을 획득하고 소멸자에서 그것을 해제하는 RAII 객체를 사용하는 상황 연출
2. 앞서와 같이 return 문으로 조기 탈출을 하여 delete가 실행되지도 않았고 명시적으로 코드 할당하지도 않음
3. 하지만 개같이 자원 해제 성공!

### 실습 결과
1. 개발자는 실수를 한다
2. 고로니 RAII 클래스를 사용하여서 자원을 획득한 후에 자원 관리 객체에게 넘기고 자원관리 객체는 자신의 소멸자를 사용해서 자원을 확실히 해제하도록 함
