# 항목 16: new 및 delete를 사용할 때는 형태를 반드시 맞추자
* new 표현식에 []를 썼으면 대응되는 delete 표현식에도 []를 써야 합니다. 마찬가지로 new 표현식에 []를 안 썻다면 대응되는 delete 표현식에도 []를 쓰지 말아야 합니다.

### 실습 요약
1. 한 개의 객체를 동적 메모리 할당하고 해제하는 케이스(delete)
2. 객체의 배열을 동적 메모리 할당하고 해제하는 케이스(delete[])
3. 객체의 배열을 동적 메모리 할당하고 delete로 해제하는 케이스
4. 1, 2의 케이스는 모두 정상적으로 할당 및 해제를 했지만 3의 케이스의 경우 *munmap_chunk(): invalid pointer* 로그를 뱉으면서 Abort됨
5. 3의 경우 delete를 했기 때문에 첫 번째 객체의 소멸자를 호출함 그리고 힙 메모리 해제를 위해 OS/glibc의 메모리 반환 함수를 호출합니다. 
6. 바로 여기서 pArrayWrong 값이 그대로 인자로 들어가게 되는데 
7. 이때 힙 관리자인 glibc가 pArrayWrong의 값을 보고(배열 시작 주소값)을 보고 나는 이런 주소로 메모리 장부 적어준 적 없는데? 칵 퉤! 하면서 코어 덤프를 뿜는다고 합니다.
8. 이일의 주범? delete 바보같이 -4 안해서 힙 관리자한테 넘겨서 그럼

### 실습 결과
1. 힙관리자는 (A) 주소로 객체를 메모리 할당해줬고 new[]가 개발자 편하라고 객체 시작점인 +4된 주소(B)로 줬는데 delete가 -4하지 않고 (B) 주소를 힙 관리자 한테 반환했다가 코어 덤프 발생 
2. 제발new 표현식에 [] 썼으면 delete에도 붙이고 안썼으면 붙이지 마라!
