# 항목 28: 내부에서 사용하는 객체에 대한 '핸들'을 반환하는 코드는 되도록 피하자.
> * 어떤 객체의 내부 요소에 대한 핸들(참조자, 포인터, 반복자)을 반환하는 것은 되도록 피하세요. 캡슐화 정도를 높이고 상수 멤버 함수가 객체의 상수성을 유지한 채로 동작할 수 잇도록 하며 무효참조 핸들이 생기는 경우를 최소화할 수 있습니다.

### 실습 요약
> 1. 실습이 캡슐화 붕괴, 댕글링 핸들(무효참조 핸들)을 설명 하고 있으며 항목 28 내용을 전부 관통함.
> 2. 보시면 Point 객체인 upperLeft와 lowerRight 모두를 private 멤버로 캡슐화 하였지만
> 3. getUpperLeft() 함수를 만들면서 복사 비용을 아끼자 참조자로 Point&로 리턴해 버립니다.
> 4. 따라서 유저가 myRect.getUpperLeft\_Bad().x = 999; 라고 치는 순간 private 멤버 데이터임에도 불구하고 참조자를 통해 원본 데이터가 접근 가능 수정 가능해지는 이상한 상황이 생깁니다.
> 5. 그래서 const Point& 로 읽기 전용으로 리턴하고자 하면 캡슐화 붕괴는 막지만 임시 객체와 엮이는 순간 댕글링 포인터 문제가 발생합니다.
> 6. 그래서 실습에서 const 를 붙여 읽기 전용으로 만들어도 const Point* pUpperLeft = &(createTempBoundingBox().getUpperLeft\_Const()); createTempBoundingBox 함수의 반환값(임시 객체)가 소멸되면서 무효참조 핸들이 생깁니다.
