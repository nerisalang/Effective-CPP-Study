# 항목 30: 인라인 함수는 미주알고주알 따져서 이해해 두자.
> * 함수 인라인은 작고 자주 호출되는 함수에 대해서만 하는 것으로 묶어 둡시다. 이렇게 하면 디버깅 및 라이브러리의 바이너리 업그레이드가 용이해지고 자칫 생길 수 있는 코드 부풀림 현상이 최소화되며 프로그램의 속력이 더 빨라질 수 있는 여지가 최고로 많아집니다.
> * 함수 템플릿이 대개 헤더 파일에 들어간다는 일반적인 부분만 생각해서 이들을 inline으로 선언하면 안됩니다.

### 실습 요약
> 1. 아무거나 인라인 하지마라. 코드가 짧은 초소형 함수에만 inline 함수를 붙여라 
> 2. 생성자나 소멸자는 절대 인라인 금지. 코드 비대화의 주범
> 3. 인라인 함수는 반드시 헤더 파일에 구현해라. 컴파일러가 치환을 하려면 호출하는 쪽에서 함수의 내부 코드를 볼 수 있어야하기 때문.
> 4. 가상 함수에 inline 붙이지 좀 마라.

### 
> **일단 아무것도 inline 하지마라**
> 병목 현상은 전체 코드의 20%에서만 발생함. 따라서 진짜 시스템의 병목 현상이 오는 핵심 1~2곳에만 인라인을 써라
> 디버깅 환경을 유지하기 위해 일단 아무것도 inline 하지마라.
> 인라인 함수는 컴파일러가 치환을 해야 하므로 반드시 헤더 파일에 내부 구현을 다 적어둬야 한다. 책의 예시에서는 라이브러리를 설계하는 사람이 inline으로 함수를 선언해서 배포시 바이너리 업그레이드를 제공할 수 가 없음. 각자의 모든 소스를 다시 컴파일 해야하기 때문임.
