# 항목 8: 예외가 소멸자를 떠나지 못하도록 붙들어 놓자

* 소멸자에서는 예외가 빠져나가면 안 됩니다. 만약 소멸자 안에서 호출된 함수가 예외를 던질 가능성이 있다면 어떤 예외이든지 소멸자에서 모두 받아낸 후에 삼켜 버리든지 프로그램을 끝내든지 해야 합니다.
* 어떤 클래스의 연산이 진행되다가 던진 예외에 대해 사용자가 반응해야 할 필요가 있다면 해당 연산을 제공하는 함수는 반드시 보통의 함수(소멸자가 아닌 함수)이어야 합니다.

### 실습 요약
1. 작업 도중 1차 에러가 발생하여 함수를 탈출(스택 되감기)을 하는 과정에서 사용 중이던 객체 W의 소멸자가 자동으로 호출되는 상황을 만듦
2. 이때 소멸자 내부에서 2차 에러가 터지게 하고 이 예외가 소멸자 내부에서 처리되지 않고 밖으로 탈출하도록 방치함
3. main함수에 try-catch문이 있음에도 프로그램을 terminate시킴

1. DBConnection::create()을 이용해서 자원을 은닉시키며 사용자가 함부로 new하거나 선언하지 못하게 막습니다.
2. dbc.close()을 이용하여 사용자가 에러를 수습할 수 있는 기회를 줍니다.
3. 소멸자 안에 try-catch문을 사용하여 예외가 소멸자를 벗어나지 않게 설계합니다.

### 실습 결과
1. 소멸자에서 예외가 빠져나가서(소멸자 안에 try-catch문이 없어) 스택 되감기 도중 이중 예외가 터져 개같이 프로그램 사망한 케이스

1. 소멸자안에 try-catch문이 있어 소멸자에서 예외를 떠나지 못하도록 붙들어 놓아서 자원 정리 다하고 safe state 만들고 곱게 뒤진 케이스
