# 항목 18: 인터페이스 설계는 제대로 쓰기엔 쉽게 엉터리로 쓰기엔 어렵게 하자.
* 좋은 인터페이스는 제대로 쓰기에 쉬우며 엉터리로 쓰기에 어렵습니다. 인터페이스를 만들 때는 이 특성을 지닐 수 있도록 고민하고 또 고민합시다. 
* 인터페이스의 올바른 사용을 이끄는 방법으로는 인터페이스 사이의 일관성 잡아주기 그리고 기본제공 타입과의 동작 호환성 유지하기가 있습니다.
* 사용자의 실수를 방지하는 방법으로는 새로운 타입 만들기 타입에 대한 연산을 제한하기 객체의 값에 대해 제약 걸기 자원 관리 작업을 사용자 책임으로 놓지 않기가 있습니다.
* *tr1::shared_ptr*은 사용자 정의 삭제자를 지원합니다. 이 특징 때문에 *tr1::shared_ptr*은 교차 DLL 문제를 막아 주며 뮤텍스 등을 자동으로 잠금 해제하는 데 쓸 수 있습니다.

### 실습 요약
1. 항목 18의 핵심이였던 타입 분리, 유효성 가드, 스마트 포인터 리턴을 활용해 좋은 인터페이스의 예를 보여줍니다.
2. 특히 날짜를 만드는 생성자에서 매개변수의 전달 순서가 잘못될 여지를 차단하기 위해 Day, Month, Year로 독립된 타입(여기선 Struct(class))로 만들어서 생성자가 명시적으로 Struct 객체를 받지 않는한 작동하지 않게 만듭니다.
3. 그리고 값의 범위를 제한하기 위해 런타임 중(A)에는 생성자 내부에서 범위 검
사를 하고 범위를 넘었다면 예외를 던져 객체 생성을 막습니다. 그리고 컴파일 중
(B)에서는 생성자를 private로 잠그고 오직 정적 팩토리 함수만 public하여 입력
자체를 차단합니다.
4. 사용자에게 자원 관리 작업의 책임을 전가하지 않게 하기 위해 스마트 포인터
*shared_ptr*를 반환하도록 하여 자원을 자동으로 해제하게 만듭니다.

### 실습 결과
1. 인터페이스를 정석적으로 사용했고 인자 순서 변경 시도도 완벽하게 차단하고 있으며 범위를 벗어나는 값의 입력도 막고 메모리 누수 차단도 완벽하게 하고 있음
